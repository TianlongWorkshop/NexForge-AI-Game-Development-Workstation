# NexForge 功能更新说明

产品 Product：NexForge · 连接锻造  
代码版本 Code version：3.0.1  
更新日期 Update date：2026-11-28  
开发工作室 Studio：天龙工坊 Tianlong Workshop

## 中文

本轮更新完善资产识别、动作模板库、动态缩图和 UE 与 Blender 的本地安装连接。重点是让已有资源能被辨认、导入、预览和用于制作，同时减少用户寻找插件目录、手动安装和重复配置的步骤。

当前代码版本仍为 3.0.1，按更新日期区分这轮改动。本说明最初记录的是三份文档交付状态；随后另行提供了 3.0.1 安装程序并随本次更新发布。该安装包由维护者单独提供，本次发布操作未重新构建或独立完成干净安装测试。

### 资产识别和封面

- 资产库支持添加文件、文件夹和拖入素材。图片、音视频、模型、Blender 工程、UE 工程及原生资产按类型展示；未知格式保留文件记录。
- UE 资产优先读取包内保存的注册信息，减少只按文件名和目录推断造成的误分类。例如，名称以 MF 或 M 开头的动画，不再仅因前缀而被当作材质。
- 有类型信息时，UE 资源可区分地图、动画、材质、贴图、蓝图等类别。人物、武器、物品等用途分类仍可能依赖命名线索，并可人工修正。
- 封面优先采用可读取的内嵌图片，其次匹配同目录同名图片。没有封面时，显示类型、名称、路径和解析状态。文件识别成功与内容预览成功分别处理。
- 对于带有效 manifest 和本地 data 文件的 Epic VaultCache 下载包，可识别清单并展开资源。下载不完整或只有分块缓存时，需要先完成下载。

### 动作模板导入

动作库支持从动画文件、UE 工程文件，以及 UE 工程或动作资源包文件夹导入。UE 工程关闭时，也能先索引原生资产并分类；不要求先将 UE 动画导出成 FBX。

原生模板保留源文件和所属工程的引用。可索引的类型包括动画序列、蒙太奇、复合动画、混合空间、瞄准偏移和姿态资产。骨架、动画蓝图、控制绑定和姿态搜索数据库与动作片段分开，避免把所有动画相关文件都当作可播放动作。

软件提供 12 个 KayKit 基础动作模板，保留来源和 CC0-1.0 许可信息。模板使用原始骨架，应用到其他角色时可能需要重定向。

### 动态缩图和滚动

- 动作模板支持悬停播放、移开停止。资产库中的 UE 动画卡片可以共用动作预览缓存。
- UE 缩图使用真实姿态采样生成骨架动作预览，用来辨认动作，不是完整材质角色的最终游戏画面。
- 混合空间显示带标注的代表动作样本。姿态资产是姿态数据，不能保证像动作序列一样连续播放。
- 首次生成 UE 预览，需要打开所属工程、连接 AIGW Bridge、提供可用的预览骨架网格。当前图集生成还使用本机 Blender。缓存生成后可离线播放。
- 动作页面、模板列表及左侧导航可以上下滚动。模板列表按可见范围绘制卡片，减少大型动作库一次性创建大量界面元素的开销。
- 修复搜索时连接栏重复，以及重新扫描资产时重建卡片打断播放的问题。

### 自动安装连接

先打开 UE 项目或 Blender，在工作台设置中点“安装并连接”。工作台识别当前软件和项目；需要区分多个目标时，列出选择，不再将手动寻找安装目录作为主要流程。

UE 插件安装到所选工程，并启用 AIGW Bridge、PythonScriptPlugin 和 EditorScriptingUtilities。修改工程描述前保留备份。如果当前编辑器已开放兼容的官方 MCP Python 接口，工作台会核对项目身份后尝试即时启用。当前 UE 5.9 已实测成功；其他环境可能需要保存并重开工程一次。

Blender 按版本安装：2.8 至 4.1 使用传统 addons 目录，4.2 及以上使用扩展目录，并配置工作台管理的启动加载器。首次安装时，已运行的 Blender 通常需要保存并重开一次；以后自动启用桥接，工作台尝试自动连接。

### 验证和适用范围

- 本机 Game Animation Sample 样本识别出 2,288 项动作与姿态模板。这是索引结果，不是每项均已生成动态缩图。
- 真实工作台窗口验证了滚轮、左侧滚动条、搜索、悬停播放、移开停止，以及重新扫描后的播放保持。
- UE 5.9 和 Blender 4.2.2 的连接、UE 关卡读取与 Blender 场景读取均成功。
- 开发完成时最后一轮自动回归为 60 项应用测试和 12 项 Python 桥接测试，均通过。

本次功能更新不是安装包构建交付；维护者另行提供的 3.0.1 安装程序随本次 Release 发布，但未在本次发布操作中重新构建或独立干净安装。未实测的编辑器版本、烘焙或加密容器、缺失依赖和不支持的包格式，仍可能影响解析与预览。

## English

This update improves asset recognition, motion templates, animated thumbnails, and local installation and connection for UE and Blender. It helps users recognize, import, preview, and use existing resources while reducing manual plugin installation and repeated configuration.

The code version remains 3.0.1; this patch is identified by its update date. This document was initially prepared as a three-document delivery; a separate 3.0.1 installer was subsequently supplied and is published with this update. The installer was provided by the maintainer; it was not rebuilt or independently clean-installed during this publishing operation.

### Asset recognition and covers

- The asset library accepts files, folders, and dropped resources. Images, audio, video, models, Blender files, UE projects, and native assets are categorized separately. Unknown formats retain a file entry.
- UE classification prioritizes serialized asset registry metadata instead of relying only on names and folders. An animation starting with MF or M is no longer treated as a material solely because of its prefix.
- Available type information distinguishes maps, animation, materials, textures, and Blueprints. Usage categories such as characters, weapons, and items may still use naming clues and can be corrected manually.
- Covers prioritize readable embedded images, then matching images beside the source file. Missing covers retain the type, name, path, and parsing status. Recognition and successful visual preview are separate outcomes.
- Downloaded Epic VaultCache packages with a valid manifest and accessible data files can be inspected and expanded. Incomplete or chunk-only downloads must be completed first.

### Motion imports

Templates can be imported from animation files, UE project files, and UE project or motion-package folders. Native indexing and classification can run with the UE project closed. Exporting native animation to FBX is not required for indexing.

Native entries retain source-file and owning-project references. Recognized types include animation sequences, montages, composites, blend spaces, aim offsets, and pose assets. Skeletons, animation Blueprints, Control Rig assets, and pose-search databases are distinguished from motion clips.

The application includes 12 KayKit basic templates with source and CC0-1.0 license information. They retain their original skeleton; other characters may require retargeting.

### Animated thumbnails and scrolling

- Motion cards play on hover and stop when the pointer leaves. UE animation cards in the asset library can share the motion preview cache.
- Native UE previews display real sampled skeletal motion, not fully textured characters or final gameplay output.
- Blend spaces display a labeled representative sample. Pose assets contain pose data and are not guaranteed to play continuously like animation sequences.
- First-time UE preview generation requires the owning project, AIGW Bridge, and a usable preview skeletal mesh. The current sprite-sheet workflow also uses local Blender. Generated caches play offline.
- The motion page, template list, and left navigation support vertical scrolling. Visible-range rendering reduces the cost of large template libraries.
- Fixes prevent duplicate connection bars during search and preserve playback when rescanning would otherwise rebuild the active card.

### Installing and connecting

Open a UE project or Blender, then choose “Install and connect” in workstation settings. The workstation detects running editors and projects, with target selection when needed. Manual directory browsing is no longer the primary workflow.

UE installation enables AIGW Bridge, PythonScriptPlugin, and EditorScriptingUtilities in the selected project, with a descriptor backup before changes. An already-enabled, compatible official MCP Python interface can activate the bridge after verifying project identity. This worked in the tested UE 5.9 environment. Other environments may require saving and reopening the project once.

Blender installation follows the version-specific layout: traditional addons for 2.8–4.1 and extensions for 4.2 or later, plus a managed startup loader. An already-running Blender normally needs one save-and-reopen cycle after first installation. Later launches enable the bridge automatically, and the workstation attempts to reconnect.

### Verification and scope

- The local Game Animation Sample fixture produced 2,288 motion and pose template entries. This is an indexing result, not a claim that every entry has a generated animated preview.
- Real-window checks covered wheel scrolling, the left scrollbar, search, hover playback, stopping on pointer exit, and playback preservation after rescanning.
- Actual UE 5.9 and Blender 4.2.2 connections succeeded, including reading their level and scene.
- The final development regression run passed 60 application tests and 12 Python bridge tests.

This feature update was not an installer build deliverable. A separately supplied 3.0.1 installer is published with this Release, but was not rebuilt or independently clean-installed during this publishing operation. Untested editor versions, cooked or encrypted containers, missing dependencies, and unsupported package formats may still affect recognition and previews.
